## 情報設計

トップは「役を見る」「点数を出す」の2択。固定下部ナビで往復する。
役はよく使う8件を先頭に、全39カード（通常役26・役満12・流し満貫の注意1）。
役名・門前/鳴き時の翻・独自の模式牌を優先し、注意は折りたたむ。
検索は漢字・かな・カタカナに対応。牌の図は手の一部であり、完全な和了例ではない。
点数は「支払う人」「1人あたり」を主表示し、供託と本場を区別する。
符が不明なら平和／七対子の近道、または4組＋ペア＋待ちを入力する。

固定ハッシュ: `#home` / `#yaku` / `#score` / `#fu` / `#rules`。
#403 learn 側は `../helper/#yaku`、`../helper/#score` を利用可能。
将来の写真認識・対局記録・成績表は #402 IDEA BOX。MVPへ混入しない。

## 計算の契約

四人リーチ麻雀の、成立した単独和了の手入力確認用。
`core.js` は DOM を参照しない純粋関数。`score(input)` と `countFu(input)` を公開。

- 基本点 = 符 × 2^(翻+2)、上限は満貫2000。親ロン×6、子ロン×4。
- 親ツモは基本点×2を3人。子ツモは親×2・他の子×1。
- 各支払者ごとに100点単位へ切り上げてから、本場をロン300／ツモ各100加算。
- 供託は千点棒の本数×1000を受取総額にだけ追加。他家の支払に混ぜない。
- 5翻満貫、6–7跳満、8–10倍満、11–12三倍満、13以上数え役満。
- 初期値は切り上げなし／数えあり／連風牌の雀頭4符。
- 切り上げありなら4翻30符・3翻60符を満貫へ。数えなしは13翻以上も三倍満。
- 実役満は倍率1–6を手入力。数え役満は1倍まで。倍率の採否は卓に確認。
- 5翻以上と実役満は符不要。1–4翻は20・25・30～110符（10刻み）を選択。
- 20符ロン、1翻20符、1翻25符、2翻25符ツモ、1翻110符ツモは拒否。
- 通常手は「ドラ以外の役あり」の明示確認が必要。写真・牌姿から役を推定しない。
- 数値の空欄・NaN・文字列・負数・小数等は拒否。翻1–99、本場/供託0–99。

符補助: 七対子25固定、平和ツモ20/ロン30。通常形は20＋門前ロン10＋ツモ2＋
雀頭＋待ち＋刻子/槓子。10符単位へ切り上げ、鳴き平和形は30符。
ロンで完成した刻子は明刻の符だが、門前状態を解除しない。
シャンポンのロン組指定漏れ、門前とポン等の矛盾を止める。
同じ牌姿の分解候補の比較・高点法・役満判定はしない。

## ルール差と一次資料

2026-09-23確認。以下を混ぜて「雀魂完全準拠」とは表示しない。
ゲーム内の点数・友人戦の卓設定を優先する。

- 日本プロ麻雀連盟「採用役一覧」: https://www.ma-jan.or.jp/activity/yaku.html
  役の成立条件、食い下がり、平和ツモ、七対子を照合。
- World Riichi / WRC Rules 2025: https://www.worldriichi.org/wrc-rules
  §11（基本点・丸め・符）、§13.4（支払表、印刷p.53）を照合。
  WRCは切り上げあり・連風牌の雀頭2符。初期設定との差はスイッチで分離。
  WRC固有の和了牌不明時の20符裁定は採用しない。
- 天鳳公式マニュアル: https://tenhou.net/man/
  四人段位戦の連風牌4符・嶺上ツモ2符、25符七対子、ロン刻子、13翻数え役満を確認。
  天鳳のその他の卓規則は一括移植していない。

## 実行・検証

ビルド・外部ライブラリ・外部フォント・認証・分析SDKなし。
HTML＋JavaScript 3ファイルを同じディレクトリに配置する。
入力はメモリ内のみ。外部送信・永続保存・オフライン再起動保証はない。

```sh
node --test core.test.cjs
python -m http.server 8765
# 別ターミナル。PlaywrightとChromiumを事前導入
CHROMIUM_PATH=/usr/bin/chromium UI_OUTPUT=./ui-results python ui-test.py http://127.0.0.1:8765/
```

今回の検証環境はローカルURL/ファイルURLへのChromium接続がポリシーでブロック。
そのため `INLINE_TEST=1` で、同じHTML/JSをDOMへ注入してUI操作を検査した。
ネットワーク経由の配信検査は別途行い、注入テストを公開URLのブラウザ実測とは扱わない。

結果（実行済み）: Node 22の241テスト成功。うち1テストで598通りの丸め・収支保存を走査。
Chromium UI 62チェック成功、JavaScript例外0。画面幅320/375/390/430/768/1280の5画面で横溢れなし。
320幅で主要button/select/固定ナビを44×44px以上と確認。かな検索・鳴きフィルタ・
親子ロンツモ・符移送・エラー・本場供託・ルール切替・再読み込み初期化・キーボード操作を確認。
スクリーンショットも目視。実機iPhone Safari／LINE内ブラウザ／家族による数秒到達は未確認。

対象外: 三麻、パオ、複数ロン、流し満貫精算、ノーテン罰符、チョンボ、
和了可否・フリテン・役の自動検出、写真からの認識、戦績保存。
